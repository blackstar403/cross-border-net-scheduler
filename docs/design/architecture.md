# SCN-01 架构

## 目标

实现“后台页面异常，先不切换出口”的控制面。系统读取已有资源并组织诊断和受控处理，不拥有代理节点、线路、隧道或业务账号。

## 组件

```text
运营输入
  -> 任务编排器
      -> 状态读取适配器 -> 已有网络工具 / 浏览器环境
      -> 任务探针       -> 允许验证的目标页面或本地模拟目标
      -> 证据分类器     -> 候选层级、反证与不确定性
      -> 动作资格闸门   -> 确认后的执行适配器
      -> 复测器         -> 同一任务成功判据
  -> 结果与审计记录
```

## 处理流

1. `REQ-OBS-01` 将自然语言整理为 `Task`。缺少目标、症状或出口约束时，任务停在 `needs_input`。
2. `REQ-OBS-02` 通过适配器读取非敏感状态。适配器必须返回能力和读取状态，不能由控制面猜测。
3. `REQ-OBS-03` 对同一目标记录处理前任务结果；探针同时返回证据来源和成功判据。
4. `REQ-DIAG-01`、`REQ-DIAG-02` 将证据分类为本地配置、DNS、连接/代理、目标响应、非网络或证据不足，并附反证和未覆盖检查。
5. `REQ-ACT-01` 调用动作资格闸门。只有满足出口约束、权限、影响范围和回退条件的动作才可请求确认。
6. `REQ-ACT-02` 在确认后委托执行适配器。执行结果是独立状态，不能覆盖任务结果。
7. `REQ-VERIFY-01`、`REQ-VERIFY-02` 在相同目标、约束和成功判据下复测，分别记录动作和业务结果。
8. `REQ-ACT-03`、`REQ-VERIFY-03` 在无动作、失败或非网络分支生成脱敏转交摘要和审计记录。

## 边界

| 模块 | 可以做 | 不可以做 |
|---|---|---|
| 任务编排器 | 追问缺失输入、维持状态机、汇总证据 | 直接修改代理、出口或业务数据 |
| 探针 | 访问允许的目标，比较同任务结果 | 用测速代替业务成功判据 |
| 适配器 | 读取最小状态，执行已验证动作 | 读取 Cookie/密码，假设其他平台能力 |
| 分类器 | 输出候选、反证和不确定性 | 将模型文本或单一信号当事实 |
| 审计记录 | 保存脱敏证据和修订历史 | 保存秘密、订单、支付和真实店铺 ID |

## 状态机

`needs_input -> observing -> diagnosed -> action_pending_confirmation -> acting -> verifying -> resolved | unresolved | handoff`

任意读取失败、权限不足、证据不足、无合格动作或非网络结论均可转入 `handoff`；只有同任务复测满足成功判据才允许进入 `resolved`。

## 首个适配器范围

首个候选是本机 Mihomo/Clash 或等价已有网络工具的适配器。当前已知的本机信息仅包括运行版本和端口观察，不代表已读到控制 API、节点连通性或出口。实现前要用脱敏测试环境完成能力探测；若无法证明出口保持和回退，适配器只提供只读状态，动作由 `handoff` 分支处理。
