- 正赛材料须审核通过后上传，报名和材料提交均不可改。9/8 已核实材料截止为 9/16 北京时间 24:00；线下路演具体日期尚待确认。
- 完整产品包括市场调研、需求分析、设计、实现、测试、交付、商业假设与用户反馈、比赛呈现，不仅是代码。七段完成定义见 [PROJECT.md](PROJECT.md)。

- 每天一个主任务，可调整工作量。延误时优先压缩界面打磨和非核心功能，保留调研、验证及报名任务。

## 每日 9 点复盘

已在 Codex 当前任务创建每日北京时间（Asia/Shanghai）09:00 的复盘任务。本文是本地查阅基线，定时执行由 Codex 自动化管理，不由本文件触发。

每次复盘：

1. 阅读本计划、仓库约束及最新确认的调整。
2. 检查本地所有分支可达的昨天北京时间自然日 Git 提交，按 SHA 去重；查看当前已暂存、未暂存与相关未跟踪改动。
3. 总结有证据的进展，附关键 SHA 或文件路径。未提交改动仅代表当前状态，不能无依据归为昨天；仓库外工作未记录则标为未知。
4. 对照日程说明偏差与阻塞，给出今天优先完成的 1 至 3 项任务及完成标准。没有提交也给简短日报。
5. 分开陈述文档计划、代码实现、模拟演示、实测和用户验证；调研、需求、试用、材料均计入进度。

关键评估节点为 **9/10、9/14、9/16、9/20、9/27、9/30**，以及后来确认的官方审核、材料、路演期限。判断继续原计划或建议调整，并说明依据、受影响任务及建议新日期。依赖阻塞或官方日期变化时提前评估，不等节点。

变更建议先写入复盘报告，用户确认后再更新本计划；不自动覆盖已确认安排。复盘不自动改代码、提交或推送 Git，也不提交官网表单或对外发消息。真实账号、密钥和个人信息不入仓库。
