# AdsPower 本地 API 技能能力核查

核查日期：2026-09-08。依据本地安装的 `adspower-browser` 技能说明和只读命令 `npx adspower-browser check-status`。该 CLI 是 AdsPower Local API 的封装，不是浏览器页面自动化工具。

## 本机状态

初始 `check-status` 返回 runtime 未运行。用户提供 API Key 后，已启动本机 AdsPower Local API，随后 `check-status` 返回 `code: 0, msg: success`。本次没有启动浏览器环境、修改 Profile、读取账号资料、Cookie 或代理配置。

只读 `get-browser-list` 返回 1 个 `Default Profile`：未配置代理、未绑定平台账号、未分组；`get-opened-browser` 返回空列表。该 Profile 只说明 Local API 的数据模型可读，**不代表真实店铺或真实代理环境已接入**。

尝试读取完整代理列表被自动审批拦截，因为响应可能包含代理地址、账号和密码。没有绕过该限制；当前 Default Profile 已明确无代理，不需要该数据来得出本节结论。

通过 MCP SDK 已完成 `tools/list`，返回 47 个工具。除 Profile/代理/分组管理外，实际还包括新建页、导航、页面文本、截图、元素点击/输入等浏览器操作工具。随后在 Default Profile 中新建标签并请求访问公开 Seller Central 入口；MCP 返回成功。为避免读取可能登录后的内容，本次没有读取页面文本、截图、Cookie 或导航响应正文。

该结果只证明**MCP 到浏览器环境的控制链路可用**，不证明入口页面已完全加载，更不证明登录后后台任务可用或恢复。由于 Default Profile 无平台账号，当前无法构造真实店铺失败问题。

### 公开入口排查试验

用户将环境切到国内网关后，希望以「我搜索亚马逊失败，是什么问题」验证 MCP 排查。MCP 只读环境状态返回国家 `cn`、代理模式 `no_proxy`、无平台账号；随后在新标签请求 Google 搜索 Amazon 与 Amazon 首页，导航工具均返回“已导航”。

但 MCP 页面文本工具未提供 Amazon 标识或标准浏览器错误代码，且其响应不是可判定的可见页面证据。截图工具指定临时路径未产生可读取文件，已确认参数语义后重试仍无临时文件；没有遍历用户目录寻找截图。未读取 Cookie、代理凭据、页面正文，也未改动环境。

正确结论：环境信号支持「当前为国内直连，出口/可达性值得优先检查」这一**候选假设**；导航成功只说明 MCP 接收请求；页面文本/截图证据不足，不能确认 Google 或 Amazon 实际失败，更不能从一句自然语言推断唯一根因。该试验是产品要求的反例：Agent 必须先区分“Google 无法搜索”“搜索结果无法打开 Amazon”“登录后特定后台页失败”，再选择检查。

若用户允许进一步验证，应使用一个不含真实账户秘密的测试 Profile，明确目标 URL 与允许读取范围，并至少取得页面错误、HTTP/导航结果或可复现探测之一。对照必须区分：MCP 动作成功、公开入口响应、真实后台任务恢复。

下表区分已证实可读的状态与技能声明可调用的其他能力，不代表本项目已完成 AdsPower 集成。

## 读写能力边界

| 能力组 | CLI 可调用操作 | 对本产品研究的意义 | 风险/边界 |
|---|---|---|---|
| 运行状态 | 检查 API 可用性、运行状态、打开的环境 | 可作为已有工具接入状态 | **已实测 API 可用，当前无打开环境**；启动需用户 API Key |
| 环境/Profile | 列表、读取 UA/活跃状态、打开/关闭；还可创建、更新、删除、移动、分享 | **已实测可列出一个无代理 Default Profile**；可获得环境状态、执行约束和浏览器启动结果 | 创建、更新、删除、移动、分享、开启/关闭均会改变状态，不应在诊断中默认执行 |
| 代理 | 列表、创建、更新、删除代理；创建/更新环境时配置代理 | 当前仅从 Default Profile 证实无代理；可确认已有代理配置和环境约束 | 完整列表未读取；代理凭据、地址、账号密码是敏感信息，不得进入诊断记录、模型上下文或日志 |
| 指纹与缓存 | 读取 UA、更新指纹、删除缓存 | 可判断浏览器环境差异 | 新指纹、删 Cookie/缓存可能影响账号和业务；不能作为自动修复动作 |
| 组织资源 | 分组、标签、应用分类、内核列表/下载、客户端补丁 | 可用于组织环境和了解版本能力 | 创建/改组/标签、下载内核、更新补丁均非只读，且不属于首版网络诊断前置能力 |
| Cookie | 读取 Profile Cookie | 不需要用于首版诊断 | **禁止使用**：包含高敏感会话数据，不读取、不存储、不传给模型 |

安装的 CLI 技能本身不支持 `navigate`、`click-element`、`fill-input`、截图等页面自动化；但另接的 `local-api-mcp-typescript` MCP 已公开这些工具，并已完成最小导航验证。故 CLI 可管理环境资源，MCP 可做浏览器页面动作；两者都不自动构成真实卖家后台异常的诊断或业务复测。

## 与前序调研的对照

此前已核对 AdsPower 公开的 Network Diagnostics：代理连接失败时检查版本、系统时间、本地网络、系统代理和端口，并可上报日志。新技能补充了一个事实：该产品还提供可由外部程序调用的本地环境/代理/Profile 管理接口。

这意味着：

1. 本产品不能只把 AdsPower 当成「有一页诊断面板」的竞品；它可以成为用户已有工具的接入对象，也可能通过其 Local API 覆盖部分受控动作。
2. 自然语言调用本地工具不构成差异。需要验证的是：能否在不泄露 Cookie/代理凭据、不改变账号环境的条件下，完成经营任务级的诊断、约束判断、复测和准确转交。
3. 本技能的危险写操作正支持我们原有的产品边界：默认只读；任何修改环境、代理、指纹、缓存或浏览器状态都必须有明确任务、前置条件、用户确认和恢复办法。
4. AdsPower 运行时已经由用户授权启动，Local API 可读取最小环境状态，MCP 也已完成公开入口新页/导航验证；但没有真实业务 Profile、授权代理或真实页面任务，不能宣称本项目已接入 AdsPower 进行业务诊断。

## 调研后的同题验证

选择一个「后台页面异常，先不换出口」的任务，在获授权且不使用真实店铺秘密的环境下比较：

| 流程 | 手工/现有 AdsPower | 拟建运维助手需要证明的部分 |
|---|---|---|
| 接入 | 客户端、Local API、Profile 是否可用 | 识别运行时/API 不可用，而不是假装已接入 |
| 诊断 | AdsPower Network Diagnostics 能处理代理连接与环境检查 | 将具体业务任务、已尝试动作和反证组织为可审计判断 |
| 动作 | Local API 可以启动/关闭环境、改代理等 | 默认不动；只有可逆、明确范围且经过确认的操作才可执行 |
| 复测 | CLI 没有页面级自动化/截图 | 以公开目标或允许的工具复测，区别探测恢复和真实后台恢复 |
| 转交 | 可获取环境状态，官方诊断可上报日志 | 生成最小脱敏摘要，避免 Cookie/代理秘密进入记录 |

这里的「拟建」不是已验证差异。若 AdsPower 配合其 MCP 或人工流程已同样完成该同题，应缩小或放弃该切入点。

## 后续可执行的任务级验证前置条件

1. 准备无真实订单、支付、账号秘密的测试 Profile，或明确允许访问的公开测试目标。
2. 提供可复现的具体症状，例如公开入口加载失败、允许的测试页面返回错误；不能将生产店铺账号异常直接用于无边界自动化。
3. 事先列出允许读取、允许导航、允许的写动作和禁止操作。默认不读取 Cookie/代理凭据，不改指纹、缓存、代理或环境。
4. 以页面/任务口径复测，并记录「MCP 动作成功」「公开入口响应」「真实业务恢复」三个不同结果。
