# 调研怎么开始，以及你怎么判断真假

公开检索得到的是**主张**，不是事实。本仓库把主张放进 `evidence.md`，每条都带：来源、等级、如何证伪。你的工作是抽验，不是再搜一篇「专线推荐」。

## 1. 先定真伪标准（四档）

| 等级 | 含义 | 可以怎么用 |
|---|---|---|
| L1 硬事实 | 官方文档、计费页、产品限制原文；你本机可复现的测量 | 可写进需求和方案 |
| L2 重复现象 | 互不隶属的卖家/论坛多次描述同一机制，无量化 | 可当痛点假设，须标「机制成立、幅度未知」 |
| L3 行业叙述 | 服务商博客、知乎专栏、SEO「评测」、带成交数字的故事 | **默认不可信**，只吸收其承认的短板 |
| L4 待一手 | 访谈、晚高峰对照、IP 共享度检测尚未做 | 不得写成已验证 |

钱潮杯材料里：L1 可陈述；L2 可当问题；L3/L4 只能写「待验」。把 L3 的「销量翻十倍」写进提交包，评委若追问样本，项目会穿。

## 2. 当前主线：只读社区与论坛

用户于 2026-09-08 明确当前不招募、不发帖，查阅已有问题、办法和竞品。执行结果见 [本轮报告](forum-research-2026-09-08.md)。

1. 搜索具体任务和错误，打开原帖与回复；搜索摘要和 AI 概览不算已核验来源。
2. 记录 URL、日期、环境、症状、尝试过的办法、结果与看不到的部分；同帖不重复计数。
3. 区分「有人建议」「作者报告有效」「受控实验复现」，不互相替代。
4. 用官方功能文档核对替代工具；描述已公开的能力，不把没找到写成没有。
5. 汇总可处理范围、不能归因的原因及候选需求；公开个案不能推算发生率、付费意愿或所有卖家需求。

以下 A/B 是后续可选实测，C 是保留的访谈模板，均不作为当前公开调研的阻塞项。

### 核验 A：链路是不是真的差（2 小时，本机）

在你平时上网的网络上，避开周末下午这种空闲时段，选一个国内晚上 20:00–22:00：

1. `ping` / `mtr` 到 `sellercentral.amazon.com`（或你实际用的站点后台）。
2. 浏览器开发者工具看后台打开时间（TTFB 和整页）。
3. 同一时刻再测一次手机热点，排除「只是家里 Wi‑Fi 差」。

记录：时刻、运营商、延迟、丢包、打开秒数。  
**判定：** 晚高峰延迟经常 >200ms 或打开 >5s，L2「后台难用」对你为真。若一直很顺，则该痛点对你不成立，项目要换场景或承认只服务差线路用户。

### 核验 B：可选出口能力验证（不是市场需求验证）

1. 办公室/家里两条业务（两个浏览器配置即可），都访问 `https://ifconfig.me` 或 `https://api.ipify.org`。
2. 看出口 IP 是否相同。
3. 若你已有加速器/专线，再测「所谓独立线路」是不是仍同一 IP。

**判定：** 同 IP 只说明本次观测的出口相同，不能证明店铺关联或隔离需求；不同 IP 也不证明独立带宽或通过风控。是否需要绑定取决于业务约束和现有工具缺口。单线路不因此排除。

### 核验 C：后续可选访谈（当前不执行）

不要问「你需不需要智能调度」。问最近一次实际故障、现有工具与处理成本，同时接受没有问题的回答：

1. 最近一次后台操作、同步或直播受阻发生了什么？你如何判断原因、处理并确认恢复？
2. 现有 Clash/代理、浏览器或服务商工具已经解决了哪些问题？还有哪一步需要人工排查？
3. 现在网是家宽、加速器还是专线？月费多少？最烦售后的哪一句？
4. 出问题你怎么知道是网还是软件？（看不看得见「这场直播掉质」）
5. 当前排查耗时、付费和采购决策如何？使用什么设备？什么问题值得再装一个产品？不预设付费档位。

把原话记在 `field-notes.md`（可脱敏）。3 人仅用于发现需求偏差，不证明目标客群普遍性。自述不自动证明网络归因；若现有方案足够，接受反证并调整场景。

可选加一项：把低价「独享 IP」拿到 https://scamalytics.com 或类似声誉查询，看是不是数据中心段、是否大量举报。脏 = 共享出口故事加强；干净也不能推广到所有服务商。

## 3. 不要用这些当「已经调研清楚」

- 服务商官网的延迟下降百分比
- 知乎「换专线销量翻十倍」（无店铺后台截图、无对照时段）
- 「23% 卖家 12 个月内登录受限」这类无样本的比例
- 火烈鸟 / OSDWAN / 悦播互评分数
- 把 Shopify 买家慢和卖家后台慢合成一个问题

## 4. 情报收集的合法范围

本项目需要的是：公开文档、可复现测量、自愿访谈。  
不要：未授权扫别人家线路、买脏代理去撞平台、把调研写成「教人规避平台风控的全套」。隔离出口是降低同网串店，不是承诺过审。

## 5. 和实现的关系

核验 C 的故障过程及现有方案缺口 → 锁定需求假设，再用对应技术实验确定可处理范围。没有访谈时可以写待验证需求，不以 A/B 通过替代市场验证。
核验 C 未做 → 需求可写，但 `evidence.md` 必须保持 L2/L4，比赛材料不得声称「已验证中小卖家付费意愿」。
