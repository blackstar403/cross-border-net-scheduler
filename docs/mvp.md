# MVP

钱潮杯周期内只做下面三件事。做完能演示，再谈下一期。

## 1. 店铺隔离

**用户能感知的结果：** 美店 A 和 TikTok 店 B 从本机出去的公网 IP 不同，演示时可截图对比。

最小实现可以是：

- 每店一条命名出口（代理 / 隧道 / 策略路由均可）
- 强制指定应用或浏览器配置走对应出口
- 一个 `check` 命令：对两店分别请求 `https://ifconfig.me` 或等价接口，打印 IP，断言不相等

非目标：住宅 IP 商城、自动买 IP、保证 IP 干净到通过平台风控。

## 2. 直播优先

**用户能感知的结果：** 点「开播」之后，同机器上的大上传（网盘、浏览器、ERP 批量）让路；停播后恢复。

最小实现可以是：

- 明确的开播 / 停播信号（手动按钮即可，不必接 TikTok Live Studio）
- 开播时限制非直播进程或端口的上行
- 记录开播窗口内的丢包、抖动、上行占用；能解释「为什么可能锁 TCP」但不必真接直播协议

非目标：自建推流中继、保证 1080p、替卖家选 CDN ingest。

## 3. 业务可见

**用户能感知的结果：** 一块极简板，三个数字，不要网速仪。

| 数字 | 含义 | 最小取数 |
|---|---|---|
| 后台打开时间 | Seller Central 或等价 HTTPS 目标的 TTFB / 全页 | 定时探测 |
| 同步失败次数 | 对 ERP / 平台 API 探测或读本地同步日志 | 计数 + 时间窗 |
| 本场是否降质 | 开播窗口内丢包或抖动是否越线 | 与第 2 项共用探针 |

非目标：全网 NPM、对标云厂商监控、给服务商的 SLA 对账系统。

## 演示脚本（比赛用）

1. 启动两店出口，跑 `check`，两 IP 不同。
2. 人为制造上行争抢（大文件上传），再开播，板子上非直播占用下降、直播探针好转。
3. 停掉其中一个出口或注入失败，板上出现同步失败 / 后台变慢，而不是只显示「断网」。

## 明确不做（本阶段）

- 独立站买家访问加速
- 云 GA / Cloudflare 配置器
- 多办公室组网、海外仓专线
- 自动购买和轮换住宅 IP
- 完整 SASE / 企业 SD-WAN 控制台
