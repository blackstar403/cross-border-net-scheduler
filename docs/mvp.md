# MVP：电商网络运维与调度闭环

2026-09-08 用户确认调整：不再以「店铺隔离 + 直播优先 + 三个数字」作为三项必做功能。产品接入卖家已有网络资源，不卖节点和线路；双出口不是前提。

## 首版范围

通过调研选定一个高频、有处理空间的经营问题，完成以下闭环。具体场景和动作待需求分析锁定，候选不等于全部实现。

| 环节 | 最小能力 | 验收依据 |
|---|---|---|
| 接入 | 读取一种已有工具或配置的必要状态，明确可观测和可控制范围 | 能判断成功、失败、权限不足；凭据不进入仓库和诊断导出 |
| 发现 | 观测选定作业异常，如后台响应异常、同步失败或直播降质 | 有来源、时间窗、正常对照；模拟数据明确标注 |
| 判断 | 根据探测和错误证据给出可疑环节及不确定性 | 区分已覆盖的本地代理、DNS、路径、目标服务或非网络错误，不声称全覆盖 |
| 处理 | 为选定场景实现一个受控动作，不满足条件则给具体建议 | 有前置条件、业务限制、执行结果及适用的恢复办法，不能只改界面 |
| 验证 | 用同一业务口径复测，记录恢复、未恢复或无法判断 | 比较处理前后；动作成功不等于业务恢复 |

仅有看板或建议页不算完整的可执行调度演示；至少一个主场景要有实际处理与复测。没有权限、资源或执行能力的分支保持建议/人工处理，不强行切换。

## 候选场景，不是必做清单

- 后台访问异常：检查代理、DNS、目标连通性；修复动作按根因证据与能力确定。
- 直播与上传争抢：限制可控制任务，停播恢复；验证争抢，明确本机与其他设备的边界。
- 同步失败：依据接口或日志区分连接错误、授权失败、限频等，不承诺修复 ERP 或平台故障。
- 路径失效：有候选且业务允许时才切换；单一路径也可诊断和给建议。
- 店铺出口绑定：用户需要且现有工具未解决时再实现。不同 IP 不代表不关联、不封号或独立带宽；既有出口稳定约束不得被静默回退突破。

Clash/Mihomo 是首个待评估的适配对象，不要求卖家购买它。一个订阅的多个节点不能自动当作多条独立线路。跨平台方向不等于所有系统的执行能力已实现。

## 演示与测试

1. 展示已接入资源、选定经营任务和正常基线。
2. 注入或复现异常，展示业务影响、诊断证据与不确定性。
3. 检查动作条件并处理，用相同指标复测，展示实际结果和记录。
4. 展示无替代路径、权限不足或处理无效之一：不误报恢复、不突破业务约束。

需求、设计、用例、演示引用同一编号。测试包含正常/异常、处理前/后对照；选定隔离或上传让路场景后，再增加对应对照，不要求所有产品都测两 IP。

## 明确不做

- 销售或自动采购节点、线路、住宅 IP，自建 POP、隧道底盘或推流中继。
- 通用 VPN、全面翻墙、独立站买家加速、Cloudflare/云 GA 配置器。
- 保证不封号、不关联，消除物理延迟或国际出口拥塞。
- 首版多租户、计费、全网 NPM、完整 SASE/SD-WAN 平台。
- 无证据自动切出口、重启网络或修改全局设置；未经实测宣称跨平台执行能力。
