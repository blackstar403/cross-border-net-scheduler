# 首版场景

## SCN-01 后台页面异常，先不切换出口

### 起点

用户发起：“这个后台页面打不开，帮我检查，先别换店铺出口。”系统将自然语言转换为一个诊断任务，但不得仅凭这句话推断根因。

### 必要输入

- 目标 URL 或可识别的页面任务。
- 用户观察到的失败表现，例如超时、DNS 错误、连接拒绝、HTTP 状态或页面持续空白。
- 发生时间和最近一次正常时间；未知时明确记录未知。
- 当前环境及允许读取的网络工具。
- `preserve_egress=true` 业务约束。

### 主流程

1. 建立任务记录并验证输入完整性。
2. 读取现有工具和本机的必要状态，记录读取成功、失败或权限不足。
3. 对同一目标采集任务结果与分层证据，至少区分本地配置、DNS、连接/代理、目标响应及非网络可能。
4. 给出候选原因、证据、反证、置信程度和未覆盖范围。
5. 检查动作是否由适配器声明可用，是否保持出口，是否有明确影响范围和恢复办法。
6. 用户确认后执行一个符合条件的动作；没有符合条件的动作时给出建议或转交，不伪造自动恢复。
7. 用同一目标和同一成功判据复测，记录处理前后结果。
8. 输出结论和脱敏记录。

### 结果分支

| 分支 | 验收结果 |
|---|---|
| 正常对照 | 页面任务成功，系统不执行修复，记录当前未复现异常 |
| 可诊断且可处理 | 动作满足约束并经确认；记录执行结果和同任务复测结果 |
| 可诊断但不可处理 | 明确原因或候选层级，说明无权限、无安全动作或需服务商处理 |
| 证据不足 | 不猜唯一根因，列出缺失证据和下一项最小检查 |
| 处理失败 | 明确动作已执行但任务未恢复；按恢复办法回退或说明无法回退 |
| 非网络反例 | 授权、限频、平台服务或页面业务错误优先转交，不执行网络动作 |

## 统一成功判据

成功必须按目标页面任务定义，例如在限定时间内获得预期 HTTP/页面标识或由允许的测试脚本确认任务完成。代理健康、导航命令返回成功、DNS 可解析或动作执行成功都不能单独代表业务恢复。

## 演示数据边界

比赛演示可用本地故障注入或公开测试目标覆盖正常、异常、处理失败/不可处理分支。界面和记录必须显示 `模拟` 或 `实测` 来源；模拟结果不得用于声称真实平台恢复率或用户价值。
