# 功能需求

以下需求共同服务 `SCN-01`。每条需求都必须由后续设计、测试和演示引用；“应”表示钱潮杯主闭环必需。

## 观测与接入

### REQ-OBS-01 建立具体业务任务

给定用户的自然语言描述，系统应建立包含目标页面、失败表现、时间窗、环境和业务约束的任务记录。必要信息不足时应追问或停止诊断，不得直接执行动作。

验收：输入只有“后台打不开”时，系统标出缺失的目标和失败表现；输入完整时生成稳定任务编号并保留 `preserve_egress=true`。

### REQ-OBS-02 读取已有资源状态

系统应通过一个已验证适配器读取诊断所需的非敏感状态，并分别报告接入成功、工具未运行、权限不足和读取失败。

验收：四类结果均可复现；输出不包含 API Key、Cookie、代理账号密码或真实店铺标识。

### REQ-OBS-03 采集同任务证据

系统应对指定目标采集带时间戳的任务结果，并保留正常基线或可比较的预期结果。模拟输入必须携带来源标记。

验收：记录包含目标、时间、成功判据、实际结果和来源；仅有通用测速数据时不得判定该后台任务异常或恢复。

## 诊断

### REQ-DIAG-01 分层分类

系统应将证据归入本地配置、DNS、连接/代理、目标响应、非网络业务错误或证据不足，不得把所有失败归因于网络。

验收：至少覆盖一个网络故障、一个非网络反例和一个证据不足用例，并输出不同结论。

### REQ-DIAG-02 展示依据与不确定性

系统应为每个候选原因输出支持证据、反证、置信程度、未执行检查和下一项最小验证。

验收：缺少页面响应证据时不能给出“已确认目标不可达”；存在互相冲突的证据时显示不确定而非选择性忽略。

### REQ-DIAG-03 避免重复无效处理

系统应记录本任务已尝试的动作和结果，不重复建议同一项已失败操作，除非新证据说明条件已经改变。

验收：同一动作失败后再次诊断时，默认进入下一项检查或转交，并引用前次失败记录。

## 受控处理

### REQ-ACT-01 评估动作资格

系统仅可展示适配器明确声明可用的动作，并在执行前核对权限、影响范围、出口保持能力、前置条件和恢复办法。

验收：任一条件未知或 `preserve_egress` 无法满足时，动作状态为不可执行，并给出原因。

### REQ-ACT-02 确认并执行一个动作

当动作资格全部满足时，系统应展示将改变的状态和恢复办法，取得用户明确确认后执行，并记录工具的实际返回结果。

验收：取消确认时零写入；确认后记录动作前后状态和执行结果。工具调用成功不得自动写成业务恢复。

注：具体动作名称由 `docs/design/scheduling.md` 在适配器验证后锁定。接口存在、按钮可点或导航成功都不足以证明动作合格。

### REQ-ACT-03 无动作与转交

没有安全动作、权限不足、疑似平台/授权问题或动作失败时，系统应停止自动处理，给出下一步和脱敏转交摘要。

验收：摘要包含任务、时间、证据、已尝试动作及结果、未覆盖项和建议责任方，不包含秘密。

## 恢复验证与记录

### REQ-VERIFY-01 同任务复测

处理或建议后，系统应使用与处理前相同的目标、环境约束和成功判据复测。

验收：输出处理前后可比较结果；无法保持同一条件时结果必须是“无法判断”，不能判定恢复。

### REQ-VERIFY-02 区分动作与业务结果

系统应分别记录动作未执行、执行失败、执行成功，以及业务未恢复、已恢复、无法判断。

验收：测试覆盖“动作成功但业务未恢复”，最终结论不得合并两种状态。

### REQ-VERIFY-03 保留可审计记录

系统应保存任务输入、证据来源、诊断版本、确认、动作和复测结论，并允许更正错误结论而保留变更痕迹。

验收：可导出单次任务记录；更正后能看到原结论、修订结论、时间和原因。
