# 需求分析

**本模块回答：** 谁在什么场景下要什么可验收结果；什么不做。

**钱潮杯完成：** 角色、三条主场景、带编号的功能需求（对应 MVP 三件事）、非功能、范围。

需求编号约定：

- `REQ-ISO-*` 店铺隔离
- `REQ-LIVE-*` 直播优先
- `REQ-VIS-*` 业务可见
- `NFR-*` 非功能
- `OUT-*` 明确不做

后续设计、测试、演示必须引用这些编号。

| 计划文档 | 内容 |
|---|---|
| `personas.md` | 无网工的店长/运营 |
| `scenarios.md` | 两店同网、开播争抢、故障不可见 |
| `functional.md` | 可测功能条目 |
| `nfr.md` | 本机可跑、密钥不入库、失败可见、隔离不可静默合流 |
| `scope.md` | 从 problem/mvp 提升的范围与 OUT 条目 |
