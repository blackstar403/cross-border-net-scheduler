# 需求分析

**本模块回答：** 谁在什么场景下要什么可验收结果；什么不做。

**钱潮杯完成：** 角色、一个调研选定的主场景、带编号的闭环需求、非功能与范围。

首版场景已锁定为：**已有联网工具的运营遇到一个明确后台页面无法完成访问，要求先诊断且不得切换店铺出口。** 首版验证发现、分层判断、受控处理或转交、同任务复测，不扩展为通用跨境任务助手。

需求编号约定：

- `REQ-OBS-*` 接入与业务异常观测
- `REQ-DIAG-*` 诊断证据与不确定性
- `REQ-ACT-*` 受控动作、条件与业务约束
- `REQ-VERIFY-*` 恢复复测与记录
- `REQ-ISO-*` / `REQ-LIVE-*` 仅在选定出口绑定/上传让路场景时使用，不是必做模块
- `NFR-*` 非功能
- `OUT-*` 明确不做

后续设计、测试、演示必须引用这些编号。

| 计划文档 | 内容 |
|---|---|
| `personas.md` | 无网工的店长/运营 |
| `scenarios.md` | 选定经营故障的发现、判断、处理、复测与失败分支 |
| `functional.md` | 可测功能条目 |
| `nfr.md` | 跨平台能力声明有证据、密钥不入库、失败可见、不得突破业务出口约束 |
| `scope.md` | 从 problem/mvp 提升的范围与 OUT 条目 |

当前需求基线：

- [personas.md](personas.md)：首版使用者、目标与前提。
- [scenarios.md](scenarios.md)：主场景、正常/失败/不可处理分支。
- [functional.md](functional.md)：`REQ-OBS-*`、`REQ-DIAG-*`、`REQ-ACT-*`、`REQ-VERIFY-*`。
- [nfr.md](nfr.md)：安全、证据、可复现及平台声明要求。
- [scope.md](scope.md)：本阶段范围、延期项与明确不做项。

状态：需求基线 V1 已形成。设计、测试和演示必须引用本文档中的编号；具体执行动作仍需在设计阶段通过适配器能力验证后锁定，不得把工具接口存在写成动作可用。
