# 非功能需求

### NFR-SEC-01 秘密最小化

凭据、Cookie、代理账号密码、真实店铺 ID、订单和支付数据不得进入仓库、通用模型上下文、诊断导出或演示数据。适配器只读取完成当前需求所需的最小状态。

### NFR-SAFE-01 默认只读

诊断阶段默认只读。任何写操作都必须通过 `REQ-ACT-01` 的资格检查与 `REQ-ACT-02` 的明确确认；系统不得静默切换出口、修改指纹、清除 Cookie、重启全局网络或改变经营数据。

### NFR-SAFE-02 失败可见

接入、探测、诊断、动作和复测的失败必须分别可见。超时、未知和未执行不得显示为成功。

### NFR-EVID-01 证据来源

每项输入和结果必须标明实测、模拟、用户描述或工具声明。产品不得用模拟结果声称真实平台、跨平台或用户效果已验证。

### NFR-PLAT-01 平台能力声明

公共诊断模型与平台执行适配器分离。每个平台分别记录已实现、已静态检查、已模拟、已实测或未验证，未测试平台不得宣称支持。

### NFR-REP-01 可复现演示

比赛环境应能用脱敏配置启动，并稳定复现正常、异常及处理失败或不可处理分支。演示不依赖真实店铺秘密或临时线上故障。

### NFR-TRACE-01 全链路追溯

设计、测试、实现说明和演示脚本必须引用对应 `REQ-*` 编号。缺少需求编号或验收证据的能力不得列为已完成。

### NFR-UX-01 面向运营表达

结果首先说明受影响的业务任务、当前结论和下一步，再展示 DNS、代理或连接等技术证据。材料不得以 Mbps、BGP 或节点数量替代业务结果。
