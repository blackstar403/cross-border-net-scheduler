**项目名称：** 跨境卖家办公网智能调度  
**赛道 / 类型：** 跨境经营类  
**阶段：** 立项（有 Demo 再改口）

## 1. 项目总览

中小卖家不是没有网，是同一条不够好的跨境链路上，直播、广告、后台、ERP、多店铺互相踩。现有服务商卖管子。我们做控制面：按店铺、按场次，把当时最好的那一跳分给最值钱的流量，并让后台打开时间、同步失败、本场是否降质能被看见。

创新点：调度对象是店铺和场次，不是 Mbps。AI 用于质量分类和是否让路，不接聊天机器人充数。

社会价值：降低「同网串店」和「开播被抢网」造成的作业失败（不承诺平台不封号）。

## 2. 市场与产品

- 客群：国内办公、2 店以上、无网工的中小团队（见 `docs/research/market.md`）。
- 痛点：只写 evidence 里 L1/L2，并写「一手核验状态」。禁止 23%、翻十倍等作废数字。
- 竞品：按层（加速器 / SD-WAN / 云 GA / 专线 / 指纹+代理），空档是控制面。
- 产品：MVP 三件事，见 `docs/mvp.md`。明确不做独立站再套 CDN、自建海缆、保证不封号。

## 3. 运营与执行

- 用户动作：绑定店铺出口；点开播/停播；看三个数字。
- 落地：本机或单办公室；卖家已有家宽或专线。
- 团队：如实写现在几人；执行力体现在「9 月能交、10 月能演示」而不是编制。
- 与连连：支付/结算不是本产品核心；可用智枢 Credits 做探测分类。跨境经营场景可提资金流与物流作业都依赖「此刻能不能干活」，不硬绑连连 API。

## 4. 财务与风险

- 杯赛阶段：无收入承诺。结构上中小卖家月费若存在，是数百到两千量级假设（L4），不要做成三年报表。
- 风险：物理延迟下限、国际出口高峰、最后一公里、平台风控多信号、代理失效、误限速。
- 应对：不承诺打破物理定律；隔离只减同出口串店；失败要可见。

## 5. 未来规划

- 6–12 个月（目标 2）：真实出口适配、单办公室试点、按店/场次看质量而不是按兆。
- 不写：自建 POP、替代阿里云 GA、德邻杯 200 万故事。
